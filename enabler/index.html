Test notes What each payment method needs before it shows up
  • Cards — nothing extra. 4242 4242 4242 4242 succeeds, 4000 0027 6000 3184 forces 3DS, 4000 0000 0000 0002 is declined. Any future expiry, any CVC.
  • Express Checkout — Apple Pay / Google Pay need HTTPS and a verified domain, so they will not appear on a plain localhost dev server. Enter a Cart ID and click Create checkout first: the express element is initialised with the cart's real currency and amount.
  • Bank transfer / BLIK — STRIPE_PAYMENT_FLOW=pi_first, the method enabled in the Dashboard for a currency your account country supports, and a cart with a customer. On submit the confirm returns requires_action and the enabler reports it through onError: that is the success path, since Stripe.js renders no UI for the funding instructions.
  • Apple Pay — HTTPS and a verified domain. The processor serves the association file at /applePayConfig from STRIPE_APPLE_PAY_WELL_KNOWN.
  • Multicapture / multirefund — STRIPE_ENABLE_MULTI_OPERATIONS=true, and multicapture enabled on the Stripe account.
